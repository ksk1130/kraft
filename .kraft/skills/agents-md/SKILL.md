# agents-md

このスキルは、リポジトリに対して `AGENTS.md` を作成・更新するための指示テンプレートです。

## 目的

- リポジトリの概要、運用ルール、開発コマンドを明文化する
- 既存の `AGENTS.md` があれば更新し、なければ新規作成する
- 新しい contributor が最短時間で安全に作業を始められるようにする
- 機密情報や秘密鍵を AGENTS.md に書き込まない

## ルール

- `AGENTS.md` はプロジェクトのルートに置く
- 既存のファイルがあれば、内容を上書きする前に既存セクションを確認する
- 重要な情報はリポジトリの実体に基づいて取得する
- README、`pyproject.toml`、`package.json`、`Makefile`、`docker-compose.yml`、`test/` などを参照して情報を集める
- 実際に使われているコマンドを優先し、推測で書かない
- 日本語の repo では日本語で、英語の repo では英語で統一する
- 追加の設定や環境変数は、必要なものだけ簡潔に整理する
- `AGENTS.md` の中で「安全に作業するための原則」を明示する

## 典型的な構成

以下の順で構成を組み立てる。

~~~md
# AGENTS.md

## プロジェクト名

- リポジトリ名と概要

## 概要

- このリポジトリが何をするか
- 主要な目的と成果物

## セットアップ

```bash
# install / init steps
```

## 主要コマンド

```bash
# build / test / lint / run commands
```

## 重要なディレクトリ

- src/
- test/
- docs/
- scripts/

## 実装方針

- アーキテクチャの要点
- 主要な責務と境界
- 変更時の注意点

## テスト

- どのコマンドで検証するか
- 重点観点

## 安全運用ルール

- 変更前に影響範囲を確認する
- 重要な操作は承認が必要
- secrets / tokens / credentials をコミットしない
- 依存関係や環境変数の詳細は必要最小限に留め、機密情報は書かない

## 変更時の注意

- 直近の実装と docs のズレを避ける
- README と AGENTS.md の説明内容を揃える
~~~

## 実行手順

1. リポジトリのルートを確認する
2. `README.md` と設定ファイルを読み、プロジェクトの目的と主要コマンドを抽出する
3. `test/` や `scripts/` を確認してテストや運用ワークフローを把握する
4. 既存の `AGENTS.md` があれば差分を最小にし、なければ新規作成する
5. 実際の repo 状況に基づいて、見出しと説明を調整する
6. 生成後に、README との説明が一貫しているかを確認する

## 出力時の注意

- 文章は要点を簡潔にし、長すぎる説明は避ける
- 例: 「どこで何をするか」「どのコマンドを使うか」「安全に作業するためのルール」を先に書く
- 実数値や構成に関する詳細は、現場のファイルに基づいて書く
- 依存関係や秘密情報は書き込まない

## 典型的な変換対象

- Python プロジェクト
- Node.js / TypeScript プロジェクト
- CLI / agent / tooling repo
- docs-first project
- mono-repo などの複合プロジェクト

## 成功条件

- `AGENTS.md` がルートに存在する
- プロジェクトの実態に即した説明になっている
- 主要コマンド、テスト、作業方針が明示されている
- README と齟齬がない
